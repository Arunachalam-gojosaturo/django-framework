Topics 2 & 3 Project vs App Architecture

Project Creation & Building an Application

Speaker Talking Point: A project represents the entire web configuration, while an app is a self-contained module that does one job (reusable component). 

# 1. Create root configuration project
django-admin startproject config .

# 2. Create the modular application
python manage.py startapp courses

# 3. Register 'courses' inside config/settings.py under INSTALLED_APPS
Topic 4 ORM & Data Modeling

Designing the Data Schema

Speaker Talking Point: Highlight how Django ORM models map Python classes to SQL tables without writing raw SQL. Point to courses/models.py:

  • Category: CharField, unique SlugField.
  • Instructor: EmailField, CharField, TextField.
  • Course: ForeignKey to Category and Instructor with on_delete=models.CASCADE and choices for status and difficulty.
  • Review: Reverse relational model for user feedback.
python manage.py makemigrations  # Generates SQL migration blueprint
python manage.py migrate         # Applies tables to SQLite db.sqlite3

❓ Common Viva & Seminar Questions (With Answers)

Q1: What is the difference between MVC and Django's MVT?

In MVC, the Controller handles incoming requests. In Django's MVT, the framework itself acts as the controller via urls.py, while the View contains business logic and the Template formats the presentation.

Q2: What is lazy evaluation in QuerySets?

Creating a QuerySet does not touch the database immediately. Django executes the database query only when the QuerySet is evaluated (e.g. in a for loop in templates or with list(), len(), or count()).

Q3: Why use a Custom Manager in Django models?

To encapsulate common filtering logic (like Course.published.all()) directly inside the model API, keeping views clean and DRY (Don't Repeat Yourself).
